# comparison-report Specification

## Purpose
定义报告的维度、结论结构、原始数据留档与发布方式。该能力要求报告能被第三方判断可信度（自述环境、公开不利数据、可复核口径），能让每个框架版本的性能变化可查询，并发布在可公开访问的位置。它服务的核心用途是**对外选型举证**：回答"为什么用 zoo 而不是裸线程、线程池或其他调度库"。

## Requirements

### Requirement: 报告 MUST 自述运行环境

每份报告 SHALL 包含产生它的环境描述，且该描述 MUST 足以让第三方判断数字的适用范围。

#### Scenario: 环境自述含硬件与软件标识
- **WHEN** 读取报告的环境章节
- **THEN** 其中包含 CPU 型号与核数、操作系统与内核版本、Python 版本

#### Scenario: 环境自述含被测对象标识
- **WHEN** 读取报告的环境章节
- **THEN** 其中包含被测框架的版本号及其源码 commit 标识

#### Scenario: 环境自述含复现命令
- **WHEN** 读取报告的环境章节
- **THEN** 其中包含产生该报告的完整命令

### Requirement: 报告 MUST 给出交叉点结论

报告 SHALL 给出"在何种执行体耗时下选择哪个方案"的结论区间，而非仅有孤立的加速比数字。

#### Scenario: 存在结论摘要章节
- **WHEN** 读取报告
- **THEN** 其中存在位于维度明细之前的结论摘要章节

#### Scenario: 交叉点由测量数据支撑
- **WHEN** 读取结论摘要中的交叉点
- **THEN** 该交叉点可由报告中的测量数据推导，且报告中给出推导所依据的档位

#### Scenario: 无交叉点时明示
- **WHEN** 全部被测档位上某一方案持续占优
- **THEN** 报告说明未观测到交叉点，并给出被测档位的取值范围

### Requirement: 报告 MUST 公开不利数据

报告中 SHALL 包含被测框架处于劣势的档位与情形。缺少此类内容的报告 MUST NOT 被发布。

#### Scenario: 不利档位被列出
- **WHEN** 测量中存在框架相对某对照方案更慢的档位
- **THEN** 该档位在报告中以与有利档位同等显著的方式列出

#### Scenario: 缺失不利数据的报告不发布
- **WHEN** 一轮测量的结果中不存在任何不利数据章节或等效内容
- **THEN** 该轮报告不被发布

#### Scenario: 口径的局限被声明
- **WHEN** 某个维度采用了不与对照方案横向比较的口径
- **THEN** 该维度的章节开头声明其口径与局限，避免读者误读为横向结论

### Requirement: 原始数据 MUST 按被测框架版本留档

每轮测量的原始数据 SHALL 以机器可读格式留档，并按被测框架版本可寻址。

#### Scenario: 原始数据可被重新渲染
- **WHEN** 使用同一份原始数据重新渲染报告
- **THEN** 渲染结果与该数据首次渲染的结果一致，无需重新测量

#### Scenario: 原始数据可按版本寻址
- **WHEN** 给定一个被测框架版本
- **THEN** 可定位到该版本对应的原始数据文件

#### Scenario: 报告可追溯到原始数据
- **WHEN** 读取报告
- **THEN** 其中指明该报告由哪一份原始数据渲染而来

### Requirement: 版本间的性能变化 MUST 可查询

harness SHALL 支持基于已留档的原始数据，产出两个框架版本之间的性能变化对比。

#### Scenario: 两版本对比可产出
- **WHEN** 对两个已留档的框架版本执行对比
- **THEN** 产出包含各维度变化方向与幅度的对比结果

#### Scenario: 缺失的版本被明确报告
- **WHEN** 对比中指定的某个版本没有留档数据
- **THEN** 该情况被明确报告，不产生以缺失数据充数的对比结果

### Requirement: 报告 MUST 发布到可公开访问的位置

报告 SHALL 由持续集成构建并发布到无需认证即可访问的位置。发布流程 MUST 可与框架仓库解耦。

#### Scenario: 报告无需认证可访问
- **WHEN** 以未登录状态访问报告的发布地址
- **THEN** 报告内容可完整读取

#### Scenario: 发布不依赖框架仓库的写权限
- **WHEN** 检查发布流程所需的凭证
- **THEN** 其中不包含对框架仓库的写权限

#### Scenario: 框架仓库提供入口
- **WHEN** 读取框架仓库的文档
- **THEN** 其中存在指向报告发布地址的链接

### Requirement: 报告 MUST 可导出为 PDF，且与其他输出同源

报告 SHALL 能由**同一份原始数据**导出为 PDF。导出 MUST NOT 引入独立于其他输出格式的数据
处理路径——各输出格式之间的数值与结论 MUST 一致，因为它们来自同一层数据抽取。

PDF 导出 MUST 正确渲染**该份产物所用语言**的文字，并 MUST 记录实际使用的字体供复核。中文产物在运行环境中找不到可用中文字体时，导出 MUST 以失败结束并给出可执行的安装指引，MUST NOT 静默降级为无法显示中文的字体后照样产出文件。英文产物的正文（含图表内文字）MUST 限制为 **ASCII**：那套字符白名单原本是按**中文字体覆盖**逐字试出来的（实测 SimHei 缺 `µ`），把 ASCII 之外的字交给它等于把方框风险重新引进英文报告；英文出现非 ASCII 字符时导出 MUST 以失败结束并指出具体文本，以便区分「漏了翻译」与「数据本身如此」。英文产物 MUST NOT 因环境中缺少中文字体而失败。

#### Scenario: 各输出格式同源
- **WHEN** 用同一份原始数据分别渲染站点报告与 PDF
- **THEN** 两者的数值与结论一致，且都不自行解析原始数据

#### Scenario: 不重新测量即可导出
- **WHEN** 对已留档的原始数据导出 PDF
- **THEN** 导出成功且无需重新测量

#### Scenario: 中文字体缺失时明确失败
- **WHEN** 运行环境中不存在任何可用的中文字体，且渲染的是中文产物
- **THEN** 导出以失败结束，错误信息指明需要安装的字体，且不产出中文无法显示的文件

#### Scenario: 英文产物不因缺中文字体失败
- **WHEN** 运行环境中不存在任何可用的中文字体，且渲染的是英文产物
- **THEN** 导出成功（英文只用 ASCII，不需要中文字体）

#### Scenario: 英文产物出现非 ASCII 即失败
- **WHEN** 英文产物的正文里出现非 ASCII 字符
- **THEN** 导出以失败结束，并指出是哪些文本——而不是任由它可能变成方框

#### Scenario: 导出记录所用字体
- **WHEN** 导出成功
- **THEN** 导出结果或日志中记录了实际使用的字体文件，使「中文为何能正常显示」可被复核

### Requirement: 报告 MUST 含开销归因维度，且结论 MUST 指出超出部分落在哪一段

报告 SHALL 含一个**开销归因**维度：在相同的档位与并发度下，给出被测框架与各对照方案四段（提交侧 / 手交 / 执行体 / 回程）各自的中位数，并给出**被测框架相对各对照方案的超出部分主要落在哪一段**的结论。该维度 MUST NOT 只给一个总开销数字。归因缺失、不可信或未探查时，报告 MUST 如实说明其状态，MUST NOT 省略该维度——省略会让读者以为它不存在。

#### Scenario: 维度在场且逐段给出
- **WHEN** 读取报告的开销归因维度
- **THEN** 其中按档位与并发度给出被测框架与各对照方案的四段中位数

#### Scenario: 结论指出段落而不是只给总量
- **WHEN** 读取该维度的结论
- **THEN** 结论说明超出各对照方案的部分主要落在哪一段，使读者知道下一步该看哪一处；只给一个总开销数字不满足本条

#### Scenario: 对照方案也逐段给出
- **WHEN** 某个对照方案参与归因
- **THEN** 它给出四段各自的中位数，而不是只给总开销——没有对照的分解回答不了"超出部分落在哪"

#### Scenario: 不可信或未探查时如实示人
- **WHEN** 该维度的自洽判据未通过，或本轮运行未包含归因探查
- **THEN** 报告给出该状态与原因，且不给据此得出的优化建议

### Requirement: 报告 MUST 含与不利数据对称的优势数据

报告 SHALL 含一个列出被测框架**处于优势**的档位与倍数的章节，其数据 MUST 与「公开的不利数据」出自**同一份同运行内的相对比**（MUST NOT 由另一次运行或另一套口径得出）。该章节 MUST 与不利数据**同等显著**（同处报告主体、结构对称），且 MUST 覆盖**全部所测档位**——MUST NOT 只列其中一部分。报告 SHALL 另含一张按执行体档位给出相对倍数的图，且 MUST 为**每一个所测并发度**各出一个面板，MUST NOT 只挑其中一部分并发度作图。

#### Scenario: 优势与不利出自同一份相对比
- **WHEN** 对照报告里的优势数据与不利数据
- **THEN** 两者的每个数字都能追溯到同一次运行的同一份逐档相对比，只是方向相反

#### Scenario: 优势章节覆盖全部所测档位
- **WHEN** 读取优势章节
- **THEN** 其中列出所有被测框架更快的档位；所测档位里没有更快的那些不出现在其中，而不是被替换成别的档位

#### Scenario: 两者同等显著
- **WHEN** 读取报告主体
- **THEN** 优势与不利两节结构对称、同处报告主体，任一方都不是脚注、附录或被折叠的内容

#### Scenario: 图按每一个并发度分面
- **WHEN** 读取相对倍数图
- **THEN** 每一个所测并发度各有一个面板；不存在"只画了部分并发度"的情形

### Requirement: 报告 MUST 把"分不出胜负"的档位单列一类，并保住全部明细

报告 SHALL 把每个（对照方案, 并发度, 档位）归入三类之一：**被测框架更快**、**被测框架更慢**、**分不出胜负**。第三类 MUST 单列成节，MUST NOT 被并入前两类中的任何一类，且其判据与所用带宽 MUST 随报告给出。正文的度量数值 SHALL 以**透视形式**呈现（行 = 并发度与档位，列 = 方案），逐单元明细 SHALL 在报告主体内的「全部数值」附录中可查，MUST NOT 因可读性而丢失或被移到报告之外。

#### Scenario: 三类各自成节
- **WHEN** 读取报告
- **THEN** 更快、更慢、分不出胜负各有一节；分不出胜负的那一节不是前两节的子集，也不是脚注

#### Scenario: 带宽随报告给出
- **WHEN** 读取"分不出胜负"那一节
- **THEN** 其中写明判据（两侧同运行内的往返离散度）与本期实际使用的带宽，使读者能判断"分不出"的依据

#### Scenario: 正文是透视而非逐单元长表
- **WHEN** 读取正文的任一度量维度
- **THEN** 该维度以行 = (并发度, 档位)、列 = 方案的一张表呈现，而不是每个单元一行

#### Scenario: 逐单元明细仍可查
- **WHEN** 读者需要分位数、离散度或各轮原始样本
- **THEN** 它们在报告主体内的「全部数值」附录中，逐单元逐字段可查，数量与改动前一致

#### Scenario: 可读化不删数值
- **WHEN** 对比改动前后的报告
- **THEN** 报告里出现的数值条目集合只增不减（新增的是三类分类与带宽说明）

### Requirement: HTML 报告 MUST 是"一页一个结论"的 deck，且必含劣势页

报告的 HTML 输出 SHALL 为固定画布（1920×1080）的幻灯片形式：每页承载一个结论、深浅页交替。承载单一数值的度量维度（延迟、框架开销、吞吐）MUST 以条形图编码**相对被测框架的倍数**，且每个条形旁 MUST 打印该点的原始数值与单位——条形只表达相对长短，精度由数字承担。该 deck MUST 含**一页列出被测框架处于劣势的档位**（含原因归类），其数据 MUST 与 Markdown / PDF 两份输出同源（由同一份报告模型得出）。当某个维度的明细多到一页放不下时，deck MUST 分页续排或给出指向全文（Markdown）与留档的指针，MUST NOT 因此省略该维度、该结论或该清单的一部分。

#### Scenario: 一页一个结论
- **WHEN** 浏览 deck
- **THEN** 每一页只承载一个结论，且正文超出该页容量时续排到下一页，而不是被裁掉

#### Scenario: 数值以条形编码且旁边有数
- **WHEN** 浏览延迟、框架开销、吞吐三个维度中任一维度的幻灯片
- **THEN** 每个方案的位置以条形给出，且条形旁打印该点的原始数值与单位

#### Scenario: 劣势页在场
- **WHEN** 浏览 deck
- **THEN** 其中含一页列出被测框架处于劣势的档位，并说明归因；该页 MUST NOT 因版面原因缺席

#### Scenario: 三种格式同源
- **WHEN** 对照 deck 与 Markdown / PDF 里同一个结论
- **THEN** 三者给出同一个数字，且都可追溯到同一份报告模型与留档

#### Scenario: 明细放不下时给指针而不是省略
- **WHEN** 某维度的逐单元明细多于一处能展示的量
- **THEN** deck 给出通往全文与原始留档的指针，且该维度在 deck 里的结论仍在场

#### Scenario: 不利数据不因版面而变小
- **WHEN** 对比 deck 里的劣势页与全文里的不利数据章节
- **THEN** 两者的档位覆盖一致，MUST NOT 只列其中一部分

### Requirement: 报告里的原始数据出处 MUST 是仓库内相对路径

三种格式（deck / Markdown / PDF）给出原始数据出处时 SHALL 写**仓库内**的相对路径（形如 `results/<框架版本>/<时间戳>.json`），MUST NOT 写构建机的绝对路径——本机是盘符路径、CI 是 runner 下的路径，两者都只在写它的那台机器上有效，而报告发布在公开站点上。路径里认不出仓库段时 SHALL 原样给出，MUST NOT 编造一个相对位置。

#### Scenario: 本机与 CI 的绝对路径折成同一形式
- **WHEN** 同一份留档在本地（盘符路径）与 CI（runner 路径）各渲染一次
- **THEN** 三种格式里的出处都是 `results/...` 形式的同一串

#### Scenario: 认不出的路径不编造
- **WHEN** 留档路径里没有可识别的仓库段
- **THEN** 报告原样给出该路径，而不是编一个不存在的相对位置

### Requirement: 站点 MUST 中英双语，且英文为主

站点 MUST 为中英两种语言各出一份**完整**的产物：每版本报告页（deck / Markdown / PDF）、站点首页、跨版本对比页。英文 MUST 位于根路径（`site/index.html`、`site/<slug>/index.html`、`site/compare-*/index.html`），中文 MUST 位于同级的 `zh/` 子目录。每一页 MUST 提供通往**同一页**另一语言版本的链接，且站点内每个内部链接 MUST 指向确实存在的文件。**缺失的译文 MUST 使渲染失败并指出缺哪个键**——MUST NOT 出现空白、MUST NOT 回落到另一种语言。两种语言页面的数值与结论 MUST 来自同一份留档，即同一次运行的数据。

#### Scenario: 两种语言各有完整产物
- **WHEN** 渲染一个已留档的版本
- **THEN** 根目录与 `zh/` 下各有 deck、Markdown、PDF 三份，且三份的数值都来自该版本的同一份留档

#### Scenario: 语言互链可达
- **WHEN** 从英文页点语言切换链接，再从中文页点回来
- **THEN** 两次都到达同一页面的另一语言版本；且站点里每个内部链接（含首页的版本卡片、对比页入口）都指向存在的文件

#### Scenario: 缺译文即失败
- **WHEN** 某个键缺少英文（或中文）文案
- **THEN** 渲染以失败结束并指出缺哪个键，MUST NOT 产出留白或混用两种语言的报告

#### Scenario: 英文产物不留中文原文
- **WHEN** 浏览英文产物
- **THEN** 其正文里的文案全部是英文，含口径局限、负载是替身声明、「不可跨运行比较」这类长段落——不把长段落留作中文原文

#### Scenario: 两种语言的数字一致
- **WHEN** 对照英文页与中文页里的同一个结论
- **THEN** 两者给出同一个数字（来自同一份留档的同一次运行）

#### Scenario: 图表的文字随语言
- **WHEN** 渲染英文产物
- **THEN** 图表的标题与轴标签也是英文，且两种语言的图表文件**不互相覆盖**
