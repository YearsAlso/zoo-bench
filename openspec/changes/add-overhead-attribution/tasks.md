## 1. 四段采集探针

- [ ] 1.1 实现带打点的执行体：与测量路径共用同一份负载，额外记录"自己开始的时刻"与"自己结束的时刻"并自报耗时；验证：它自报的耗时与测量路径同一档位的分位数同量级
- [ ] 1.2 实现四段采集：提交侧（调用提交入口到它返回）、手交（提交返回到执行体开始）、执行体（执行体自报）、回程（执行体结束到排空返回）；验证：在**同一个**受测对象上跑一遍，四段之和与同一次实测的端到端一致
- [ ] 1.3 计时区间内不做任何 I/O：原始样本留在内存，只把聚合结果交出；验证：探查运行期间没有任何写文件/打印（源码级守卫 + 运行期断言各一条）
- [ ] 1.4 新增探查入口 kind，与既有 kind 并列；验证：`python -m zoo_bench.worker attribution <spec> <out>` 能独立跑完并落盘，且失败时 stderr 有真实堆栈

## 2. 被测框架的细分与插桩成本

- [ ] 2.1 包装被测框架的接缝（设 worker 列表、走一次调度轮、调度内核登记、调度模型派发），**不改框架代码**；验证：包装前后同一档位的端到端中位数差异即插桩成本，且被如实记录
- [ ] 2.2 把提交侧细分为 `call_workers`、内核登记、模型派发、每轮策略查询；验证：细分项之和与提交侧那一段一致（容差内），细分只重排不新增也不吞掉时间
- [ ] 2.3 逐条声明用到的插桩接缝（含"每轮策略查询"对应框架里的哪个入口）；验证：结论里能逐条读出接缝，读者据此能判断这份分解的口径
- [ ] 2.4 确认细分只对被测框架做；验证：对照方案的结果里没有细分项，且报告写明深度不同是**因为结构不同**

## 3. 编排与报告维度

- [ ] 3.1 把探查结论收进结果结构（与 `semantics` 同一处收口，失败不上升为阻塞）；验证：留档里含该维度；探查失败时如实标记而不是让整轮失败
- [ ] 3.2 报告模型新增该维度；验证：缺省时为"未探查"占位（与既有语义维度的做法一致），**不省略**
- [ ] 3.3 抽样档位固定且写明：矩阵里最短的一档与一档长档位 × 最低与一个中等并发度；验证：报告写明抽了哪些档位，且探查时长不随矩阵规模膨胀
- [ ] 3.4 短档位不给分解：低于既有"档位长度"那条线的档位不出分段数值，并给出原因；验证：短档位的条目只有状态与原因，没有分段数字

## 4. 自洽与可比性判据

- [ ] 4.1 四段之和与端到端的一致性判据；验证：注入一处分解错误（例如把回程算进提交侧）后该判据判否，该次归因被标为不可信
- [ ] 4.2 判据的鉴别力双向验证；验证：正确分解下判据通过、且注入违规后必红（只读代码不足以判定其有鉴别力）
- [ ] 4.3 可比性判据：不同档位或不同并发度的段不得并列成结论；验证：混档位输入被判否，而不是算出一个看起来正常的值
- [ ] 4.4 确认该维度**不参与**任何门禁；验证：把某档位的开销人为做高，汇报与门禁都不变（开销高低是结论，不是错误）
