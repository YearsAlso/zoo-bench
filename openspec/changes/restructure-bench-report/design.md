## Context

见 `proposal.md`。本轮**只动信息架构**：不改视觉设计语言、不改测量与统计口径、不删数值。所有改动必须能从已留档的 `results/**/*.json` 重新渲染出来（**不跑测量**）。

本轮对象是 `results/zoo-framework-0.10.0/20261008T131339Z.json`（参考稿 `design/report-redesign-draft.html` 与任务书里的全部数字都出自它）。

## Goals / Non-Goals

**Goals:**

- 报告先给结论，再给证据：读者在前三页就知道"多大的任务该用哪个方案"。
- deck 从"全文的分页版"变成一份设计过的、页数收敛的演示，且不因此丢任何结论或任何一个数值。
- 对比页只列有判读意义的行。
- 三种产物（deck / Markdown / PDF）继续同源；双语继续完整。

**Non-Goals:**

- 不改测量、留档格式、矩阵清单、适配器与负载。
- 不改交叉点判定、带宽判定、三类分类、超订撤下、"不可跨运行比较"这些口径骨架。
- 不重做调色板、字阶、字体；不引新的第三方依赖。
- 不重排 Markdown 全文既有的章节阅读顺序（除结论区新增两节与去重外）。

## Decisions

### D1 选型速查**复用**已有的三分类，不另立判据

单元格取值规则（全部来自 `_classify_relative` 那一次分类，不重新比较）：

1. 取该 (并发度, 档位) 上**比值最小**的对照方案；
2. 该方案落在「被测框架更慢」类 → 单元格 = `方案 1/比值 x`；
3. 落在「被测框架更快」类（意味着被测框架比**全部**对照都快且超出带宽）→ 单元格 = 被测框架自己；
4. 落在「分不出胜负」类 → 单元格 = 「分不出」；
5. 该格一个对照方案都没有 → 单元格 = 「无数据」。

**为什么复用三分类而不是重算一遍**：带宽是"两侧跨轮离散度之和"，它随档位变化；再写一份比较逻辑就会与优/劣/平三节给出互相矛盾的结论。复用意味着选型速查的每一格都能在三节里找到出处，且"分不出"与「分不出胜负」一节逐字同义。

**替代方案**：另写一份"取最小值 + 固定百分比阈值"的判定（否决：两个带宽会让同一份报告自相矛盾）；在渲染层从格式化后的字符串反解（否决：把格式当数据，单位一改就静默取错）。

### D2 摘要只留三句，逐档列举交给矩阵

`report.summary.*` 保留：被测框架自身的交叉点（`crossing_found` / `crossing_missing` / `overhead_all_unreadable`）、最好的一个优势档（`favourable_best`）、指向两张矩阵的引导（新增 `summary.matrices`）。删除逐条 `turning_found` / `turning_missing`。

**为什么保留 `favourable_best`**：只讲"对照方案从多大档位起不再更快"是负向表述，读者得自己反推优势；两个方向对称，句子结构与交叉点那几句一致。

### D3 转折点改为矩阵，两种"空"要分开

「相对转折点」由"每行一个 (方案, 并发度) 的 4 列表"改为**行 = 对照方案、列 = 并发度**的矩阵。单元格取 `first_tier_baseline_not_faster_us`：

- 有值 → 该档位（并说明它是所测档位中**最小的**满足者，真实转折点落在它与前一档之间）——这一句由**表下一条共同说明**承担，不再逐行重复；
- 无值 → 「未观测到」，并当场说明**那是本期结论而不是缺数据**（该方案在所测档位内始终更快）；
- 该方案在该并发度下**没有单元** → 「无数据」（与上一者成因不同，必须分开说）。

`_relative_turnings` 里逐行的 `note` 一并去掉（它与表下共同说明逐字重复）。

**替代方案**：保留逐行 note 只去掉参数（否决：仍然是 20 处重复文本，读者要读 20 遍才知道是同一句话）。

### D4 进程隔离：模型层就把原始结构换掉

`model["absolute"]["process_isolation"]` 原先是**留档里的原始字典**（`parent_pid` + 九十多个 `child_pids`）。本轮改为**可读摘要**：`present` / `unit_count` / `distinct_pid_count` / `duplicate_count` / `all_distinct` / `none_equals_parent`。

**为什么在模型层换掉而不是在渲染层不打印**：留在模型里的原始结构，任何一个后端都可能顺手把它印出来——而"把 PID 列表印满一页"这件事本身不会让任何功能断言变红。模型里没有它，就谁都印不出来。原始字典仍在留档 JSON 里（那是机器可读数据，本来就不该进报告正文）。

`all_distinct` 为假时报告给出**解释或标注为待查**（PID 复用是常见原因），`none_equals_parent` 为假时如实说出。字段缺失或为空字典时**跳过该条**（沿用"缺字段则跳过"的既有风格），不报错。

### D5 deck 按语义切页，指针降级为页脚一行

- 删除 `SLIDES_PER_SECTION` 截断与 `_pointer_slide_for()` 整页指引。被截断的那一页在**页脚**点名送去全文的哪一章（`deck.content.source` 已在做这件事，把它写成带章节名的指针即可）。
- 删除 `deck.content.suffix`（「（续）」）作为**页标题**的用法。续页的标题由内容决定：不利数据按**对照方案分组**命名，图表按**并发度与档位区间**命名。
- `SLIDE_ROW_CAP` / `_CHARS_PER_ROW` 保持不变——它们描述的是版面容量（`.slide` 是 `overflow: hidden`），不是"每节最多几页"这种编辑策略。页数由内容量除以容量得出，不再由常量截断。

### D6 一个维度在 deck 里只讲一遍

保留条形图（相对倍数、越长越差、统一方向），透视表**不再进 deck**（它仍在全文里）。一个维度一页，用左右分栏容纳全部档位；装不下时按档位区间分页而不是按行数硬切。

**为什么砍掉透视表**：同一个维度的两种读法（倍数 vs 绝对值）并排出现，读者要来回换算；而绝对值在全文与附录里一个都没少。

### D7 对比页折叠：复用同一条带宽

- **不可读组**（并发度超出机器并行能力或开销为负）折成**一行统计**：点名哪些组、共多少行、原因，并链接到说明。这类行逐行铺开时，读者从中读不出任何版本差异。
- **变化落在带宽内**的行折成计数。带宽取**与报告同一条**定义：两侧各自的**跨轮相对离散度之和**（把 `report._unit_round_spread` 提为公开函数 `unit_round_spread` 复用，不另写一份）。样本不足算不出带宽的行按"不判定"处理，单独计数。
- **绝对耗时表不折叠**：它整表都标着"不可跨运行比较"、用途是看量级，每一行都是有效信息。

**替代方案**：用一个写死的百分比阈值（否决：与报告的带宽判据不一致，同一份站点的两处输出会对"差异算不算数"给出不同答案）。

### D8 占位符标点检查放进 `t()`

任务书要求"i18n 模板不得以句号/句末标点结尾（或对应的等价检查）"。字面规则会误伤整个目录——绝大多数模板本来就以句号结尾。故取**等价且精确**的检查：模板里若某个参数占位符**紧跟**句末标点，而该参数的值本身又以句末标点结尾，则渲染**失败**并指出键名。

这正是本轮的 bug 形态：`compare.withheld.note` 在 `{note}` 后紧跟句号，而 `note` 的内容（`caliber.uninterpretable_reason`）自带句号。规则落在 `t()` 里，故对所有键、两种语言、任何调用点都成立。

**替代方案**：用例里扫全部模板、禁止占位符后接标点（否决：会连带否掉 14 处合法写法——那些参数是数值或方案名列表，永不以句末标点结尾，去掉标点反而读不通）。

### D9 页数预算：16 页（实测）

deck 的页序列与依据：

| 序 | 页 | 依据 |
|---|---|---|
| 01 | 封面 | 既有 |
| 02 | 一句话结论（三个大数字） | 摘要里最面向决策的三个数：开销阈值交叉点 / 最短档的开销占比 / 本期最大劣势倍数 |
| 03 | 选型速查 | D1 |
| 04 | 转折点矩阵（含被测框架自身阈值一行） | D3 |
| 05-07 | 相对倍数图 × 3 个维度 | D6：一维度一页 |
| 08 | 赢在哪 + 分不出胜负（分不出独立成段并给计数） | spec 要求第三类单列 |
| 09 | 公开的不利数据：归类卡片 | spec：劣势含原因归类 |
| 10-12 | 公开的不利数据：完整清单续排到底 | spec：不利数据不因版面而变小。25 档分三页是**数据量**决定的（每组对照方案的档位不可拆开），不是编辑策略 |
| 13 | 开销归因 | 取每任务超出最大的几档 + 维度状态；完整明细见全文 |
| 14 | 调度语义的代价 | 既有维度 |
| 15 | 可复核性（环境 + 自检结论，无 PID 列表） | D4 |
| 16 | 全文与原始数据 | 既有收尾 |

合计 16 页 = 验收上限。**页数随数据增长**（不利数据一档不少），这是 spec 明文要求的代价；用例对全尺寸矩阵钉住"≤16 且中英页序一一对应"，而不是对当期数据钉一个数字。

**两处按语言长度做过取舍**（英文逐字比中文长，按内容长度决定页数会让两种语言的页数对不上）：可复核性那一页只放**自检结论**与读数口径的**引导**，三条读数纪律的正文留在全文（它英文侧 18 行、中文侧 6 行，两栏也装不下）。归因那一页同理只列超出最大的几档并明说这是前几档。

**替代方案**：把不利数据的完整清单也压成一页（否决：25 行放不进 14 行上限，压进去只能靠删行，直接违反 spec 的「不利数据不因版面而变小」）；按内容长度分页（否决：中英页数会对不上）。

## Risks / Trade-offs

- **deck 页数对新矩阵敏感**：矩阵变大时不利数据与图表页会各自增长。这是"不许因版面而变小"的必然代价；页数上限由用例对**全尺寸**模型断言，而不是对当期数据断言。
- **对比页的信息量下降**：折叠掉的行不再逐行可见。缓解：折叠行给出计数与分组名，且逐单元数值仍在两个版本各自的报告与留档里。
- **选型速查的单元格是二元判断**：格子里只有"谁最快"与倍数，不表达"快多少才算快"以外的信息——带宽判据写在表下，不塞进格子。

## Migration Plan

一次性切换：块层与 deck 同一次改动内完成，没有中间态。旧留档可重新渲染（本轮所有结论都由留档数据导出，不依赖测量实现）。
