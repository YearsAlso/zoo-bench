## Why

deck 报告目前只能靠**点击左右半屏或按方向键**翻页（框架脚本自带的是这两个，实测没有滚轮处理）。读者的第一反应是滚轮，滚了没反应就以为"这页到底了"——一份要给人看的报告不该这样。

另外每页的内容是**一起出现**的：一页里有标题、正文、表格、页脚，视觉上没有先后，读者不知道从哪里开始看。

## What Changes

- **滚轮翻页**：滚轮上/下翻页，带**阈值与冷却**（触控板一次手势会连发几十个 `wheel` 事件，不设阈值一划就跳五页）。行模式的 `deltaMode` 要换算，否则 Firefox 的滚轮会被阈值全部挡掉。
- **入场的错开淡入**：每页元素按序淡入并轻微上移（标题 0ms → 正文 40ms → 表格 80ms → 页脚 120ms，约 40ms 一档）。当前页被切到前台时重新播放一次。
- **数值类动画**：大数字滚动到目标值、图表条形从零增长。这两条改的是**数字本身**，故另有两条硬约束——收尾 MUST **逐字**写回渲染时的原值（不是重新格式化）；打印（含打印恰好发生在滚动途中）与 `prefers-reduced-motion` 下 MUST 直接呈现真值。**已知取舍**：滚动途中截图会拍到中间值，这条无法通过实现消除，只能靠"不做数字滚动"消除——效果是被明确要求的，故做，并把风险记在设计里供将来重新权衡。
- **两处必须的收敛**（不是可选项）：`prefers-reduced-motion: reduce` 下**不播动画**；**打印时动画完全失效**——否则打印会抓到初始态（`opacity: 0`），打出来是空白页。
- **顺带修掉一个打印缺陷**（在实施核验时发现，不是原先计划的一部分）：框架的打印规则被屏幕规则的选择器具体度压掉，实测一份 38 页的 deck 用浏览器打印**只出当前那一页**。补一条同具体度、排在其后的规则放开非当前页。
- **不改 vendored 框架块**：三个标着 DO NOT EDIT 的资产保持**字节不变**（它们被 sha256 钉着）。滚轮与动画都通过框架本来就留的扩展口接入：往 `window` 发 `{type:'od:slide', action:…}` 驱动翻页，收它广播的 `{type:'od:slide-state', active}` 决定给哪页挂动画。
- **不引 anime.js**（或任何动画库）：要的效果是 `opacity` + `translateY` 的错开淡入，CSS 关键帧十来行就够；库会带来 ~17 KB/页 的内联体积（5 个目标 × 2 语言），而 deck 必须自足（它会被单独转发、作为归档产物长期存在），从 CDN 引更是给"能离线打开的文档"接了个外部失败点。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `comparison-report`：现有条款只要求 HTML 是 deck 形态，没规定怎么翻页。新增一条：deck MUST 支持滚轮翻页，且 MUST 在 `prefers-reduced-motion` 下不播动画、在打印时不留动画初始态。

## Impact

| 类别 | 文件 |
|---|---|
| deck 渲染 | `src/zoo_bench/render/deck.py`：`_EXTRA_CSS` 加入场关键帧与两处收敛；新增一小段自己的脚本（拼在 vendored 脚本之后） |
| 测试 | `tests/test_render_deck.py`：滚轮处理器在场、vendored 脚本里**没有** wheel（证明是追加而非改写）、reduced-motion 与 print 的规则在场、动画初始态不覆盖无 JS 的读者 |
| 不动 | 三个 vendored 资产（哈希用例继续钉住）、测量、留档、矩阵、口径、另三份输出格式的形态 |

**边界**

- 不做页内滚动（每页是固定 1080px 且内容已按行数分页，没有可滚的东西）
- 不做自动播放、不做进度条、不做幻灯片间的过渡动画（只做元素入场）
- 不翻页到两端之外：框架的 `go()` 本来就做钳制，越界即停（不循环）
