  - 其它实测事实（供后续组使用）：① 路由形态的决策开销约 13 µs（`decide` 每次新建 `random.Random()`），故小帧上路由形态**慢于两种形态**（22.4 > 17.1 > 8.9 µs）——报告的不利章节有真实数据可放；② 规模分界实测在 21 B 与 255 B 之间（21 B 档原生并不更快），与框架自述的"≥21 字节划算"不同——后者是**解析口径**，本线是**worker 口径**（含契约查找 + 输入输出转换的固定开销约 15 µs），报告须按实测如实分界；③ 门禁输入若取 257 字节，两臂的 `NativeInvalidInput` 消息不同（框架适配器的边界前置检查先说话），故判据输入集 MUST 落在任务声明的输入上限内。
  - 探针脚本（一次性，弃于临时目录）：`%TEMP%\native-line-spike\spike_forms.py`、`spike_refuse_a.py`、`spike_equiv.py`、`spike_tiers.py`
- [x] 1.3 实测决策粒度：确认统计与决策按 **Worker 类名**索引（同一类的不同规模共享一条统计）；验证：用两个不同的类名跑同一规模，统计快照里出现两条独立条目；用一个类名跑两个不同规模，快照里只有一条——这条实测结论是 D4「每规模一个类」的依据，若与预期不符则先停下来改设计
  - 实测（2026-10-11 同轮探针）：一个类名 `RoutedWorker` 跑 7 字节与 21 字节两档共 80 次提交 → 快照**只有一条** `RoutedWorker` 条目、`n` 之和 = 80，其 python 臂均值被两档**混合**（8.35 µs 与 11.97 µs 混成一个均值）；再加入第二个类名 `RoutedWorkerAlt` 跑 21 字节 30 次 → 快照变成**两条**独立条目；同类名再跑 21 字节 30 次 → 仍是两条，`RoutedWorker` 的 `n` 由 80 涨到 110。结论与 D4 预期一致（统计与决策均按类名索引、跨规模共享），D4「每规模一个 Worker 类」成立，无需改设计。
  - 附带实测：ε=0.05 下 600 次提交的探索臂次数为 12–22 次（比例 2%–3.7%，低于 ε 的名义值但同量级），两种规模上都能观察到探索臂样本——报告须给出探索率与逐臂次数（规格已要求）。

  - 实测（2026-10-11，0.11.0 + `zoo-framework-native` 0.1.0）：15 条判据输入（含异常响应帧 `0x83`/`0x84`，其 `exception` 字段为解析**成功**的业务结果）上与真扩展**逐字节**相等，`mismatches == []`。逐字节相等蕴含逐字段相等，且更强（键序、分隔符、数值格式都在内）。
- [x] 2.2 等价性门禁：输入集含**正常 / 受控失败 / 坏 CRC** 三类，两臂输出逐字节比对，不等即判否并给出不等价的输入；验证：注入一处违规（如把 CRC 高低字节调换）后门禁变红，按 md5 逐字节还原后通过
