## Context

现状见 proposal.md 的 Why。设计上要接的三处接口：`:mod:`zoo_bench.render.report`` 已把三种格式统一到**一份块列表**（design D11 的"同源"保证）；:func:`zoo_bench.render.blocks.build_blocks` 产出的块是**与输出格式无关**的（标题/段落/条目/表格/图/注）；`zoo_bench.report.build_model` 的模型里各类数值是**原始浮点数**（未格式化）。

模板（用户提供）的边界已经标清：第一个 `<style>` 块、`deck-counter`/`deck-hint` 导航、`<script>` 三段标了 DO NOT EDIT；第二个 `<style>`（逐页样式）与 `<section class="slide">` 页体是槽位。

## Goals / Non-Goals

**Goals:**

- HTML 输出换成 deck 形态，且**逐页内容由模型生成**（不手写数字）。
- 框架块原样 vendor，不改一个字符。
- 劣势页在场且**覆盖完整**（与全文不利章节的档位集合一致）。

**Non-Goals:**

- 不改 Markdown / PDF 的产出形态，不引入无头浏览器。
- 不改跨版本对比页（另一份文档）。
- 不改测量、留档、矩阵、口径。

## Decisions

### D1 同源：文字取自块，数值取自模型，用用例钉住一致

Deck 的**文字**（标题、段落、条目、表头与表体单元格）取自 `build_blocks` 的块，故措辞与 Markdown/PDF 必然一致。Deck 的**条形图**取自模型里的原始数值——块的表格里已经是格式化后的字符串（`108.6 微秒`），从字符串反解数值等于把格式当数据，且单位一改就静默取错。

故 deck 渲染器的入参是 `(model, blocks)`，两者由 `report.render` 同一次调用传入。一致性由用例钉住：deck 里的英雄数字（档位计数、开销占比）必须与 Markdown 正文里的同一结论等值。

**备选**：给 `Block` 加数值字段 → 否决。为一个后端污染三个后端共用的层，而那个层存在的理由恰恰是"格式无关"。

### D2 逐页映射由块驱动，页数随内容增长

一个一级/二级标题开启新页；其后的段落、条目、表格、图归入该页。表格按行数上限切分（见 D3 的风险控制）。**不写死页数**。

劣势清单一页列不下时**分页续排**，这是 spec「MUST NOT 只列其中一部分」的落法——按行切、不按重要性截。

**备选**：照模板写死 12 页 → 否决。内容一变就漏（模板自己就漏了三个基线方案），且劣势页会被"页数不够"挤掉。

### D3 框架块原样 vendor，逐页样式与页体由代码生成

三段标 DO NOT EDIT 的区域（第一个 `<style>`、导航与提示 HTML、`<script>`）原样进 `render/deck_framework.html`，渲染器只做拼接，不重写不重排。`<style>` 里的 `:root` 是模板自己标注的 SLOT（主题令牌），由本 deck 填。

每张 `slide` 带 `data-screen-label`，便于对照与排错。

**备选**：把框架 CSS/JS 抄成 Python 字符串字面量 → 否决。那是"不可改"的部分，抄进代码里就多了一处会漂移的副本。

### D4 `.src` 页脚与劣势页是硬要求

模板的每页页脚 `.src` 写"这一页的数来自哪"——保留，且**每页都要有**：deck 是脱离上下文被转发的（PPT/单页截图），页脚是唯一还在的出处。

劣势页不是"想放才放"的收尾页，是 spec 强制的门槛，且渲染前由既有发布门禁再拦一道。

### D5 PDF 仍由 reportlab 出，不引入无头浏览器

模板的 `@page { size: 1920px 1080px }` 只对浏览器打印生效。要让 PDF 也变成幻灯片页，需要 CI 里装无头浏览器（约 300MB）并把渲染从纯函数变成进程调用——换来的只是"同一份内容排成幻灯片页"。

故：HTML 是 deck，PDF 仍是 reportlab 的可分发文档，Markdown 仍是可 diff 的全文（附录明细在这里）。三者的**内容**同源（D1），**形态**各有理由。

**备选**：装 Playwright 出 PDF → 否决。引入新的第三方依赖（按本仓库规则须先确认）且收益仅在排版。

### D6 站点链接不变，另把 Markdown 也列出来

`index.html` 这个名字让 deck 直接顶上，版本卡片的"报告"链接无需改。首页目前只列 PDF，Markdown 不列——而 deck 把逐单元明细交给了 Markdown，故首页**加上** Markdown 链接（明细不再"要另外找"）。

## Risks / Trade-offs

- **`overflow: hidden` 会静默截断**（`deck-stage` 与 `slide` 都设了）→ 版面溢出不会报错，只会少一截内容，而"少一截"最难被发现。缓解：渲染器对每页做**元素数与行数上限**检查，超限即抛（分页也按同一常量切），并有用例钉住"超限即抛"。
- **中文落到系统字体**：模板字体栈以 Berkeley Mono 起头、以 `monospace` 收尾，CJK 由浏览器回退到系统字体。缓解：保留模板栈原样，不引入 web 字体（离线可用优先）；字号与行高已经按 CJK 行高 ≥1.3 定过。
- **报告正文的字符门禁**：既有 `assert_report_text_is_renderable` 管的是中文字体覆盖（缺字变方框）。Deck 的文本同样要过这道门（deck 的 `×`、`−` 等一律用 ASCII），否则会出现"HTML 正常、PDF 方框"的不一致。
- **deck 与块措辞漂移**：缓解即 D1 的用例。
- **文件体积**：框架块约 12 KB 内联进每份 deck，每个版本目录各一份。体积可接受（对齐既有 `style.css` 的做法）。

## Migration Plan

纯渲染层变更，无数据迁移。已发布的旧报告目录保持原样（下次渲染时被 deck 覆盖 `index.html`）；回滚即回退代码后重跑渲染。
