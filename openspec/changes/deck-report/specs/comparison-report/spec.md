## ADDED Requirements

### Requirement: HTML 报告 MUST 是"一页一个结论"的 deck，且必含劣势页

报告的 HTML 输出 SHALL 为固定画布（1920×1080）的幻灯片形式：每页承载一个结论、深浅页交替。承载单一数值的度量维度（延迟、框架开销、吞吐）MUST 以条形图编码**相对被测框架的倍数**，且每个条形旁 MUST 打印该点的原始数值与单位——条形只表达相对长短，精度由数字承担。该 deck MUST 含**一页列出被测框架处于劣势的档位**（含原因归类），其数据 MUST 与 Markdown / PDF 两份输出同源（由同一份报告模型得出）。当某个维度的明细多到一页放不下时，deck MUST 分页续排或给出指向全文（Markdown）与留档的指针，MUST NOT 因此省略该维度、该结论或该清单的一部分。

#### Scenario: 一页一个结论
- **WHEN** 浏览 deck
- **THEN** 每一页只承载一个结论，且正文超出该页容量时续排到下一页，而不是被裁掉

#### Scenario: 数值以条形编码且旁边有数
- **WHEN** 浏览延迟、框架开销、吞吐三个维度中任一维度的幻灯片
- **THEN** 每个方案的位置以条形给出，且条形旁打印该点的原始数值与单位

#### Scenario: 劣势页在场
- **WHEN** 浏览 deck
- **THEN** 其中含一页列出被测框架处于劣势的档位，并说明归因；该页 MUST NOT 因版面原因缺席

#### Scenario: 三种格式同源
- **WHEN** 对照 deck 与 Markdown / PDF 里同一个结论
- **THEN** 三者给出同一个数字，且都可追溯到同一份报告模型与留档

#### Scenario: 明细放不下时给指针而不是省略
- **WHEN** 某维度的逐单元明细多于一处能展示的量
- **THEN** deck 给出通往全文与原始留档的指针，且该维度在 deck 里的结论仍在场

#### Scenario: 不利数据不因版面而变小
- **WHEN** 对比 deck 里的劣势页与全文里的不利数据章节
- **THEN** 两者的档位覆盖一致，MUST NOT 只列其中一部分

### Requirement: 报告里的原始数据出处 MUST 是仓库内相对路径

三种格式（deck / Markdown / PDF）给出原始数据出处时 SHALL 写**仓库内**的相对路径（形如 `results/<框架版本>/<时间戳>.json`），MUST NOT 写构建机的绝对路径——本机是盘符路径、CI 是 runner 下的路径，两者都只在写它的那台机器上有效，而报告发布在公开站点上。路径里认不出仓库段时 SHALL 原样给出，MUST NOT 编造一个相对位置。

#### Scenario: 本机与 CI 的绝对路径折成同一形式
- **WHEN** 同一份留档在本地（盘符路径）与 CI（runner 路径）各渲染一次
- **THEN** 三种格式里的出处都是 `results/...` 形式的同一串

#### Scenario: 认不出的路径不编造
- **WHEN** 留档路径里没有可识别的仓库段
- **THEN** 报告原样给出该路径，而不是编一个不存在的相对位置
