## Context

动机见 `proposal.md`。现状（实测一份报告）：正文里「公开的不利数据」是 MUST 的独立章节，而**优势那一面没有任何章节**；图只有「框架开销占比」与「吞吐」两张，前者是被测框架短档位上最难看的一面，后者在高并发下量到的是排队。**两者都表达不了"多大的任务用哪个"**，而那正是这份报告的用途。

数据其实已经在场：`relative.comparisons[].ratios_vs_subject` 逐（对照方案、并发度、档位）给出"对照方案耗时 / 被测框架耗时"，报告模型的 `conclusion.relative_turnings` 也已经在用同一份数据讲"对照方案从多大档位起不再更快"——只是从未取它 `> 1` 的那一半正面呈现过。

## Goals / Non-Goals

**Goals**

- 被测框架**在哪些档位、相对哪些方案更快**，在报告主体里一眼可见
- 优势与不利**同源同显著**：两者来自同一份同运行内比值，故谁都无法只挑对自己有利的档位
- 不改动「公开的不利数据」那一节

**Non-Goals**

- 不弱化不利数据（内容、位置、显著度都不动）
- 不做营销式措辞：不给"显著领先""大幅超越"这类评价词，只给同源数字
- 不改测量、留档与跨版本对比
- 不为"图好看"挑并发度或挑档位

## Decisions

### D1 · 优势与不利**同源**，这是能正面呈现的前提

- **选**：优势数据从 `relative.comparisons[].ratios_vs_subject` 取（`> 1` 的那一半，即被测框架更快）；不利数据取同一份的 `< 1` 那一半。
- **理由**：同源意味着**覆盖范围相同**——两边都是"全部所测档位"，不存在的档位不会因为好看而被补上、难看的档位也不会被摘掉。一份报告里正面呈现自己的优势之所以可信，就靠这一点。
- **已考虑的替代**：另算一套"加速比"指标（拒绝：两套口径必然漂移，而漂移的方向总是对自己有利）。

### D2 · 图为按并发度**分面**的小多图，不挑并发度

- **选**：一张「相对倍数」折线图，每个所测并发度一个面板；x 轴是全部执行体档位（对数，跨两个半数量级），每个对照方案一条线，`y = 1` 画一条打平基准线（`y > 1` 即被测框架更快）。
- **理由**：挑一个并发度作图就是挑对自己有利的呈现——而这恰恰是这类图最容易失守的地方。分面让全部并发度同时在场，读者自己看形状。
- **代价**：面板多了图会小。接受的取舍——四张小图比一张好看的大图更诚实。

### D3 · **不动不利数据**，优势节紧邻它之前

- **选**：「公开的不利数据」的内容、位置与显著度一律不变；优势节插在它**紧邻之前**，两者构成对称的一段。
- **理由**：把不利项往后挪或缩小，等于改一条硬要求的含义（"必须公开"变成"可以藏一点"）——而本次不需要那样做也能达到"优势可见"。读者按"赢在哪 / 输在哪"的顺序读这两节，任一方都不是脚注。
- **已考虑的替代**：把不利数据挪到文末（拒绝：那是降低显著度，需要单独的决定与规格措辞变更，本次不做）。

### D4 · 摘要补一句正面表述，措辞与既有结论句同构

- **选**：结论摘要里补一句"在并发度 X、执行体时长不超过约 Y 时，被测框架比 Z 快，最多 N 倍"，数字来自同源比值。
- **理由**：既有摘要只讲"对照方案从多大档位起不再更快"（一个负向表述），读者要自己反推优势。补上正向的那句，两个方向对称。
- **代价**：摘要变长两句。接受的取舍——摘要的用途就是给不看细节的读者一个完整印象，只给一半方向不算完整。

## Risks / Trade-offs

**[优势章节被读成营销] → ** 缓解：同源同覆盖（D1）、不利数据原样在场（D3）、措辞与既有结论句同构且不含评价词（D4）。

**[图为好看而失真] → ** 缓解：按并发度分面、x 轴覆盖全部档位、`y = 1` 基准线显式画出（D2）。

**[优势与不利两节的措辞不对称，读者仍只读到一半] → ** 缓解：两节的结构（表头、列、口径注）刻意保持一致，只有"方向"不同。

**[图的面板变多导致 PDF 里过小] → ** 缓解：面板数由矩阵里的并发度个数决定（当前 4 个）；若日后并发度档位变多，图会变密——那时把分面改成"每行两个面板"的多页排布，而不是删掉面板。
